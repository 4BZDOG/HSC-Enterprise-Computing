# Contributing to HSC Enterprise Computing Notes

Thank you for helping improve these notes. The site is written for Year 11 and 12 students and their teachers, so accuracy against the NESA syllabus matters more than anything else. This guide explains the workflow, the style rules and the tools.

## Getting started

### Prerequisites
- Git
- Python 3 (the scripts use only the standard library)
- A modern browser and a text editor
- Node.js, only if you add or edit Mermaid diagrams (`npm install` once, then `npm run diagrams`)
- Basic HTML and CSS for content or layout changes

### Local setup
1. Fork the repository on GitHub, then clone your fork:
   ```bash
   git clone https://github.com/YOUR_USERNAME/HSC-Enterprise-Computing.git
   cd HSC-Enterprise-Computing
   git remote add upstream https://github.com/4BZDOG/HSC-Enterprise-Computing.git
   ```
2. Preview with a local server (opening `index.html` directly can break the theme and storage):
   ```bash
   python3 -m http.server 8000
   # then visit http://localhost:8000/
   ```

## Workflow

1. Create a branch: `git checkout -b claude/short-descriptive-name` (or `content/…`, `fix/…`).
2. Make your change (see below) and preview it in light and dark mode and at phone width.
3. Run the checks (see [Checks before a pull request](#checks-before-a-pull-request)).
4. Commit with a conventional message, push, and open a pull request using the template.

Commit types: `feat:` (new content or feature), `fix:`, `docs:`, `style:`, `refactor:`, `perf:`, `test:`. Keep commits atomic and explain why, not just what. Do not commit `resources/spec-pages/`, PDFs or screenshots (they are ignored).

## Style rules

### Language
- **UK / Australian English**: organisation, visualisation, analyse, behaviour, licence (noun), program (software), programme only for TV. Use the syllabus's own spellings when quoting it.
- **Inclusive language**: no gendered pronouns for hypothetical people; realistic Australian enterprises (a regional hospital, a Service NSW-style agency, a farm co-op, a local retailer, a logistics firm, a start-up).
- **Accuracy over flourish**: no invented statistics, dates, quotes, company claims or legislation. If you are not sure of a figure, describe the idea without it. Australian context first (Privacy Act 1988 (Cth) and the Australian Privacy Principles, the Notifiable Data Breaches scheme, the Cybercrime Act 2001, the Essential Eight and so on).
- **Indigenous content** (ICIP, Indigenous Data Sovereignty, the CARE principles): be respectful, accurate and specific; refer to Aboriginal and Torres Strait Islander Peoples; do not invent protocols.

### The verbatim-syllabus rule
`resources/nesa-syllabus-content.md` is the source of truth. On each focus-area page, the part names (`.part-name`), each dot point (`<p class="syllabus-concept">`) and each "Including" list (`<ul class="syllabus-including">`) are NESA's words, verbatim and in NESA's order. They are generated by `scripts/scaffold-page.py`, and `scripts/check-site.py` fails if they change. You may improve the `<h2>` heading and the outcome codes in `.outcome-subtitle` (only codes from that focus area's own outcome list), but never reword the syllabus text. If NESA changes the syllabus, update `resources/nesa-syllabus-content.md` and `scripts/page_specs.py` first.

### NESA command verbs and depth
Write each section at the depth its verb asks for:

| Verb | Expect |
|---|---|
| Identify, outline, describe, define | Concise and precise |
| Explain, examine, compare, distinguish | Causes, effects and relationships, with examples |
| Investigate, evaluate, assess, research, justify | Several perspectives, criteria, pros and cons, a judgement |
| Apply, use, select, develop, design, implement, configure | A worked, step-by-step example students can reproduce (formulas, SQL, a diagram, configuration steps) |

Cover every "Including" item under its own `<h3>`. `python3 scripts/copy_audit.py` lists each section's length against the scope its verb implies. NESA's Course Specifications (`resources/ec-course-specifications.md`) are integral to the course: use its symbols, SQL keywords, spreadsheet functions and testing and implementation methods exactly.

### Code and design
- **Vanilla only**: no external JavaScript or CSS libraries and no CDNs. Fonts and icons are local or inline.
- **Storage keys** start with `ec-` (the site shares an origin with the Software Engineering site). `check-site.py` enforces this.
- Use the theme's CSS custom properties (`var(--primary)`, `var(--surface)` …) so light and dark mode both work; no inline `style` attributes. Shared styles live in `css/styles.css` and `css/theme.css`.
- Respect `prefers-reduced-motion`. Every page must work at 375 px wide with no horizontal scrolling.
- Sources: link only to reputable, stable sources (NESA, OAIC, ASD/ACSC, eSafety, legislation.gov.au, W3C, ABS, AIATSIS and similar), and check each link returns HTTP 200.

## Adding or editing content

### Editing a focus-area page
1. Open the page in `topics/` (for example `topics/data-science.html`).
2. Replace each `<!-- CONTENT: … -->` placeholder and its `<p class="content-placeholder">` with your notes, inside the existing `<section id="…">`. Leave the heading area, `.syllabus-concept` and `.syllabus-including` alone.
3. Write the header description and the `<meta name="description">` / Open Graph / Twitter descriptions (120 to 160 characters), the topic introduction and each part's breakout.
4. Replace the sample quiz questions (see [Quizzes](#quizzes)).
5. Run `python3 scripts/check-site.py --strict` to confirm no placeholders remain on your page.

Never hand-edit the navigation, mobile menu, footer, previous/next cards, `?v=` cache-busting queries or the sidebar and title icons: `python3 scripts/site-chrome.py` rewrites them on every page.

### Content components
- **Callouts**: `<div class="callout tip|info|warning|danger|success|assessor"><strong>Label</strong> …</div>`. Use `assessor` for HSC exam guidance (how a question on this dot point is likely to be worded, common mistakes, what a full-mark answer includes). Aim for at least one per part.
- **Key terms**: `<div class="key-terms"><div class="key-term"><dt>Term</dt><dd>One precise sentence.</dd></div></div>`.
- **Tables**: wrap in `<div class="table-wrap"><table>…</table></div>` so they scroll on phones.
- **Code**: `<div class="code-block"><pre><code class="language-sql">…</code></pre></div>`. Use only the SQL keywords in the Course Specifications unless you flag something as an extension.
- **Figures**: every diagram sits in a numbered `<figure class="figure">` with a kicker (kind of diagram), a title, a one-sentence lead, a "What to notice" list and a "Try this" prompt.
  ```html
  <figure class="figure">
    <figcaption class="figure-head">
      <p class="figure-kicker"><span class="figure-kind">System flowchart</span></p>
      <h4 class="figure-title">Title</h4>
      <p class="figure-lead">One sentence on what it shows.</p>
    </figcaption>
    <div class="figure-canvas figure-canvas--still"><div class="anim" data-anim="scene-name"></div></div>
    <div class="figure-notes">
      <div><h5>What to notice</h5><ul><li>The learning point.</li></ul></div>
      <p class="figure-try"><strong>Try this</strong>A short task using the diagram.</p>
    </div>
  </figure>
  ```

### Adding a new page: the scaffold workflow
Focus-area pages are generated, not copied.

1. Add or check the entry in `scripts/page_specs.py`: one row per dot point with a section id, a student-friendly heading, outcome codes and the start of NESA's wording. `python3 scripts/restructure.py <slug>` checks it against the syllabus and stops with a clear message if they disagree.
2. Add the page to `PAGES`, `ICONS` and (for a syllabus topic) `SEQUENCE` in `scripts/site-chrome.py`.
3. Generate the skeleton:
   ```bash
   python3 scripts/scaffold-page.py <slug>          # refuses to overwrite an existing page
   python3 scripts/scaffold-page.py <slug> --force  # regenerates it, discarding hand-written content
   ```
   It writes the head, breadcrumbs, header, sidebar, parts, sections, quiz placeholders and scripts, and creates `js/quizzes/<slug>.js` if missing. The Resources pages `toolkit`, `project-guide` and `example-project` are generated as "coming soon" pages until written.
4. Add the home page card (`index.html`) and a `<url>` entry in `sitemap.xml`.
5. Run `python3 scripts/site-chrome.py`, then the other checks.

The full step-by-step is in `.claude/skills/add-topic.md`.

### Quizzes
Each focus-area page has one quiz per part (`<div class="quiz" data-quiz="<prefix>-<N>">`; prefixes are `im`, `net`, `cyber`, `ds`, `dv`, `is`, `ep`). The questions live in that page's own file, `js/quizzes/<slug>.js`:

```js
window.HSC_QUIZZES = Object.assign(window.HSC_QUIZZES || {}, {
  'ds-1': [
    { q: 'Question text', options: ['A', 'B', 'C', 'D'], answer: 2, why: 'Why C is right.' },
  ],
});
```

Write about five questions per part, mixing recall with scenario (application) questions in the style of HSC objective items. Use four plausible options, vary the correct index and always fill in `why`. `check-site.py` fails if a quiz on the page has no questions, if a bank has questions for a quiz the page lacks, or if an answer index is out of range.

### Glossary terms
Terms live on `topics/glossary.html`; `js/glossary-data.js` is generated from it and powers the inline popovers. Do not edit the data file by hand.

1. Add terms to `scripts/glossary_new_terms.py` as `(id, name, [topic keys], definition, example)`. Topic keys: `im`, `net`, `cyber`, `ds`, `dv`, `is`, `ep`, `toolkit`, `project`. Prefer NESA's definition where `resources/ec-syllabus-glossary.md` has the term.
2. Run:
   ```bash
   python3 scripts/add-glossary-terms.py    # inserts new terms alphabetically into topics/glossary.html
   python3 scripts/build-glossary.py        # regenerates js/glossary-data.js
   python3 scripts/site-chrome.py           # adds the topic icons to the new terms' tags
   ```
3. To stop a very common word being auto-linked in prose, add its id to `NO_AUTOLINK` in `scripts/build-glossary.py` (for example `term-enterprise`); to add an alternative spelling, use `EXTRA_ALIASES`.

The Certified Resources page is generated too: edit the link lists in `scripts/build-resources.py` and run it.

### Diagrams
Every diagram is a numbered `.figure` (see above) with alt text, no emoji inside the drawing and text no smaller than 13 px. Notation follows the NESA Enterprise Computing Course Specifications (`resources/ec-course-specifications.md`): system flowchart symbols, data flow diagrams, flowcharts with BEGIN/END terminators and labelled decision exits, decision trees, storyboards, network diagrams, graph theory, Gantt charts and schemas.

- **Still and animated diagrams** use the same kit as the Software Engineering site. Put `<div class="anim" data-anim="name"></div>` inside the figure canvas and draw the scene in `js/anims/<name>.js`. Read `.claude/skills/paper-diagrams.md` for still diagrams (the notation rules and a template) and `.claude/skills/add-animation.md` for animated ones (style guide, scene API and template). Link `css/anim.css` and `js/anim.js` once on any page that uses them.
- **Structure charts and data flow diagrams** are drawn by `js/nesa-diagrams.js` from data in `js/nesa-diagram-data.js`: `<div class="nesa-diagram" data-diagram="key"></div>`.
- **Mermaid** is pre-rendered, so pages load no diagram library. Write the source in `<div class="mermaid">…</div>`, then run `npm install` (once) and `npm run diagrams`. The source stays in a `<template class="mermaid-source">`; edit it there and run the command again (`npm run diagrams:all` redraws everything). `check-site.py` fails if a diagram is undrawn or was edited after drawing.
- New scene files and diagram-data keys take the page's prefix (`im-`, `net-`, `cyber-`, `ds-`, `dv-`, `is-`, `ep-`, `tk-`, `pg-`, `ex-`) so contributors never collide. Reuse an existing scene before drawing a new one.

## Checks before a pull request

```bash
python3 scripts/site-chrome.py          # navigation, footer, icons, ?v= hashes
python3 scripts/build-glossary.py       # js/glossary-data.js
python3 scripts/build-mapping.py        # resources/Syllabus-Mapping.md
python3 scripts/check-site.py           # add --strict for a finished page
bash scripts/validate-alignment.sh
```

`check-site.py` and `validate-alignment.sh` also run on every pull request (`.github/workflows/checks.yml`). Then check by eye:

- [ ] Page loads without console errors and all links work
- [ ] Light and dark mode both look right
- [ ] 390 px wide: no horizontal scrolling; tables scroll inside `.table-wrap`; figures readable
- [ ] Keyboard navigation works; figures have alt text
- [ ] Quizzes and glossary popovers work

## Submitting

Push your branch and open a pull request against `main`, filling in the template: what changed and why, the syllabus and source checklist, the checks you ran, and before/after screenshots for visual changes. Respond to review comments by pushing to the same branch. When the pull request merges, `.github/workflows/deploy.yml` publishes the site.

## Getting help

- Questions or ideas: open a discussion or an issue.
- Found a mistake in the notes: open a bug report naming the page and section, ideally with the syllabus dot point it concerns.
- Stuck: read `README.md`, `CLAUDE.md` and `reference/CONTENT_BRIEF.md`.

## Code of conduct

Be respectful and inclusive, give constructive feedback, and assume good intent. See [.github/CODE_OF_CONDUCT.md](.github/CODE_OF_CONDUCT.md).
