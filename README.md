# HSC Enterprise Computing Notes (EntComp Notes)

> Study notes for NSW HSC Enterprise Computing (Year 11 and 12), following the NESA Enterprise Computing 11–12 Syllabus (2022) dot point by dot point.

**Live:** https://4bzdog.github.io/HSC-Enterprise-Computing/

---

## Overview

EntComp Notes is a free, static website for students and teachers of the **NSW Higher School Certificate Enterprise Computing** course. Every page follows the syllabus in NESA's own order: one page per focus area, one part per NESA subheading and one section per dot point, with the dot point quoted verbatim, its "Including" list, the outcome codes it addresses, and notes written at the depth its NESA command verb asks for.

The site is plain HTML, CSS and JavaScript. There is no framework, no external JavaScript library and no build step for readers. Python scripts (standard library only) generate the shared navigation and footer, the glossary data and the syllabus mapping, and check that the pages still match the syllabus.

It is a sister site to [HSC Software Engineering Notes](https://4bzdog.github.io/HSC_SoftwareEngineering/) and shares its approach; the two sites share an origin, so every browser-storage key here starts with `ec-`.

## Features

**Content**
- Every syllabus dot point in NESA's order, with the verbatim wording, "Including" lists and outcome codes; a script fails the build if any of it drifts.
- Notes pitched to the NESA command verb: brief for *describe* and *outline*, broader for *investigate* and *evaluate*, worked and reproducible for *apply*, *develop* and *design*.
- HSC exam guidance in `assessor` callouts, aligned to the 80-mark, 2 h 30 min online exam format.
- Australian context first: privacy and cyber law, Indigenous Cultural and Intellectual Property (ICIP) and Indigenous Data Sovereignty, and realistic enterprises.
- A syllabus mapping (`resources/Syllabus-Mapping.md`) from every dot point to the section that covers it.

**Study tools**
- Multiple-choice quizzes at the end of each part, with explanations.
- A searchable, filterable glossary, and inline definition popovers on first mention of a keyword in each section.
- Reading progress remembered in the browser only; nothing is sent anywhere.

**Diagrams**
- Still and animated diagrams drawn with the same kit as the Software Engineering site (`js/anim.js`, scenes in `js/anims/`).
- Structure charts and data flow diagrams drawn by `js/nesa-diagrams.js` from `js/nesa-diagram-data.js`.
- Mermaid diagrams pre-rendered to inline SVG (`npm run diagrams`), so pages load no diagram library.
- Notation follows the NESA Enterprise Computing Course Specifications: DFDs, flowcharts, system flowcharts, decision trees, storyboards, network diagrams, graph theory, Gantt charts and schemas.

**Design and accessibility**
- "Data Studio" theme with light and dark modes (preference saved as `ec-theme`; respects `prefers-color-scheme`).
- Responsive from phone width; semantic HTML, ARIA labels, keyboard-navigable menus, reduced-motion support.
- SEO metadata on every page: canonical URL, Open Graph and Twitter cards, JSON-LD breadcrumbs, `sitemap.xml` and `robots.txt`.

## Local preview

The site is static, so any file server works. From the repository root:

```bash
python3 -m http.server 8000
# then open http://localhost:8000/
```

Use a server rather than opening `index.html` directly, so that the theme, storage and relative links behave as they do on GitHub Pages. Requirements: Python 3. Node.js is needed only for `npm run diagrams` (run `npm install` once first).

## Checks

Run these before opening a pull request:

```bash
python3 scripts/site-chrome.py          # apply the shared navigation, footer, icons and ?v= hashes
python3 scripts/build-glossary.py       # regenerate js/glossary-data.js from topics/glossary.html
python3 scripts/build-mapping.py        # regenerate resources/Syllabus-Mapping.md
python3 scripts/check-site.py           # syllabus text and order, outcomes, quizzes, links, ids, markup, figures, generated files
bash scripts/validate-alignment.sh      # syllabus alignment report
```

`check-site.py` fails on real problems and lists unfinished `<!-- CONTENT: … -->` placeholders as notes. Add `--strict` for the final pre-release check, which also fails while any placeholder remains. Both `check-site.py` and `validate-alignment.sh` run on every pull request through `.github/workflows/checks.yml`.

## Deployment

The site is hosted on **GitHub Pages** at https://4bzdog.github.io/HSC-Enterprise-Computing/.

- `.github/workflows/deploy.yml` runs on every push to `main` that changes a public file (`index.html`, `404.html`, `topics/**`, `css/**`, `js/**`, `robots.txt`, `sitemap.xml`, `og-image.png`), or manually from the Actions tab.
- It checks that each page opens with `<!DOCTYPE html>`, then copies **only the public files** into a `_site/` folder and uploads that. `reference/`, `resources/` (including the Course Specifications PDF and page images), `scripts/` and `.github/` are never published.
- In the repository settings, set **Pages → Source** to **GitHub Actions**.
