# Skill: add-topic

Use this skill when asked to add, scaffold, regenerate or fill in a topic page for **HSC Enterprise Computing Notes** (NESA Enterprise Computing 11–12 Syllabus, 2022). Read `CLAUDE.md`, `CONTRIBUTING.md` and `reference/CONTENT_BRIEF.md` first.

Site: https://4bzdog.github.io/HSC_EnterpriseComputing/ (a sister of the Software Engineering site, which is read-only reference: never modify it).

---

## Two kinds of page

| Kind | Examples | How it is made |
|---|---|---|
| **Focus-area page** (a NESA focus area) | `interactive-media`, `networking-systems`, `cybersecurity` (Year 11); `data-science`, `data-visualisation`, `intelligent-systems`, `enterprise-project` (Year 12) | Generated by `scripts/scaffold-page.py` from `resources/nesa-syllabus-content.md` + `scripts/page_specs.py` |
| **Resources page** | `toolkit`, `project-guide`, `example-project` (stubs from `scaffold-page.py`); `glossary`, `resources` (built by `build-glossary.py` / `build-resources.py`) | Stub generated, then written by hand |

The syllabus dot points, "Including" lists and part names on a focus-area page are NESA's words, verbatim and in NESA's order. **Never reword them.** `scripts/check-site.py` fails if they change.

## Required inputs (ask if not supplied)

| Field | Example |
|---|---|
| `slug` | `data-science` (kebab-case; also the file name and the quiz file name) |

## Steps

### 1  Describe the page in `scripts/page_specs.py` (focus-area pages only)

Add an entry to `SPECS` keyed by slug:

```python
'data-science': {
    'focus_area': 'Data science',          # NESA title, verbatim
    'title': 'Data Science',
    'year': 12,
    'quiz': 'ds',
    'parts': [                             # one list per NESA subheading, in order
        [
            # (section id, heading, outcome codes, start of the dot point's text)
            ('data-collection', 'Collecting Data', 'EC-12-02, EC-12-04', 'Research, source, organise and store'),
            ...
        ],
        ...
    ],
},
```

- One tuple per dot point, in NESA's order; the last item must be the start of that dot point's syllabus text.
- Section ids are unique within the page. Outcome codes come only from the focus area's own `*Outcomes:*` line in the syllabus file.
- Check it: `python3 scripts/restructure.py <slug>` lists the sections, or stops with a clear message if the syllabus and the spec disagree (missing, extra or reordered dot point, duplicate id, foreign outcome code).
- If NESA uses a multi-word leading verb that the scaffold does not bold correctly, add it to `VERBS` in `scripts/restructure.py`.

### 2  Register the page in `scripts/site-chrome.py`

Never edit the nav, mobile menu or footer by hand. In `site-chrome.py`:

- `ICONS['<slug>']`: the inner markup of a 24×24 stroke icon (stroke only, simple paths). It appears in the nav, footer, page title, sidebar title, pager and home card.
- `PAGES['<slug>'] = ('y11' | 'y12' | 'core', '<Title>', '<one-line summary>')`.
- `SEQUENCE`: add the slug in course order if it is a focus-area (syllabus) page; this places it in the previous / next topic cards.

### 3  Generate the skeleton

```bash
python3 scripts/scaffold-page.py <slug>            # refuses to overwrite an existing page
python3 scripts/scaffold-page.py <slug> --force    # regenerates; DISCARDS hand-written content
python3 scripts/scaffold-page.py --all             # every page (use --force with care)
```

For a focus-area page it writes `topics/<slug>.html` with: the head (title, description, canonical, Open Graph, Twitter, JSON-LD breadcrumbs, favicon, `ec-theme` init, css links); navigation, mobile menu and footer shells; the topic header (breadcrumb, h1, year / hours / outcome pills, "Curriculum aligned" card); a sidebar contents list; a topic introduction; then per NESA subheading a part banner and breakout, and per dot point a `<section id>` with the heading, `.outcome-subtitle`, the verbatim `.syllabus-concept`, the `.syllabus-including` list and a `<!-- CONTENT: … -->` placeholder; a `.quiz` placeholder at the end of each part; and the script tags. It also creates `js/quizzes/<slug>.js` with one sample question per quiz key if the file does not exist (it never overwrites a quiz bank).

For a Resources stub (`toolkit`, `project-guide`, `example-project`), add or edit its text in `STUBS` in `scaffold-page.py` first.

### 4  Apply the shared chrome

```bash
python3 scripts/site-chrome.py
```

This fills the navigation dropdowns, mobile menu, footer, icons, pager and `?v=` hashes on **every** page. Run it again after every change to `PAGES`, `ICONS`, `SEQUENCE`, `css/` or `js/`.

### 5  Home page and sitemap

- **`index.html`**: add a `.topic-card` to `#year11` or `#year12` (or the Resources grid), using the same inline SVG as `ICONS['<slug>']` in `.card-icon`, a "Focus area NN" kicker with hours, a description, the outcome range and dot-point count, and three `.topic-tag` items. Update the section's `.topic-count`, and the hero and "Course at a glance" figures if totals change (currently 7 focus areas, 140 dot points, 22 outcomes, 240 hours).
- **`sitemap.xml`**: add a `<url>` with `https://4bzdog.github.io/HSC_EnterpriseComputing/topics/<slug>.html`, today's date as `<lastmod>`, `<changefreq>monthly</changefreq>` and `<priority>0.9</priority>`.

### 6  Write the content

Replace every `<!-- CONTENT: … -->` and its `content-placeholder` paragraph. Follow `reference/CONTENT_BRIEF.md`. In short:

- **Depth follows the NESA verb** (see the table in `CONTRIBUTING.md`); about 250 to 700 words per section, more for heavy practical dot points; cover every "Including" item under its own `<h3>`.
- Improve the `<h2>` and outcome codes only; leave `.part-name`, `.syllabus-concept` and `.syllabus-including` untouched.
- Write the header description and the meta / Open Graph / Twitter descriptions (120 to 160 characters), the topic introduction, and each part's breakout.
- **Exam guidance**: at least one `<div class="callout assessor">` per part.
- Use NESA Course Specification notation and SQL/spreadsheet syntax exactly (`resources/ec-course-specifications.md`).
- **UK / Australian English**; Australian context; inclusive language; no invented facts.

### 7  Quizzes

Each part ends with `<div class="quiz" data-quiz="<prefix>-<N>">`. In `js/quizzes/<slug>.js` replace the sample with about five questions per part:

```js
window.HSC_QUIZZES = Object.assign(window.HSC_QUIZZES || {}, {
  'ds-1': [
    { q: 'Question', options: ['A', 'B', 'C', 'D'], answer: 2, why: 'Why C is right.' },
  ],
});
```

Mix recall and scenario questions like HSC objective items; four plausible options; vary the correct index. `check-site.py` checks that every quiz on the page has a bank entry (and vice versa), that keys start with the page's prefix, and that answer indexes are in range. The page loads its own bank (`js/quizzes/<slug>.js`) before `js/quiz.js`.

### 8  Glossary

Add each new keyword to `scripts/glossary_new_terms.py` as `(id, name, [topic keys], definition, example)`. Topic keys: `im`, `net`, `cyber`, `ds`, `dv`, `is`, `ep`, `toolkit`, `project`. Prefer NESA's definition (`resources/ec-syllabus-glossary.md`). Then:

```bash
python3 scripts/add-glossary-terms.py && python3 scripts/build-glossary.py && python3 scripts/site-chrome.py
```

The inline popovers on your page come from `js/glossary-data.js` (first mention per section). Keep very common words out of the auto-linker with `NO_AUTOLINK` in `build-glossary.py` (already set for `term-enterprise`).

### 9  Diagrams

Every diagram sits in a numbered `<figure class="figure">` (kicker, title, lead sentence, "What to notice", "Try this"), with full alt text, no emoji inside the drawing and text at least 13 px. Use the shared kit, never hand-written SVG:

- **Still and animated diagrams**: `<div class="figure-canvas figure-canvas--still"><div class="anim" data-anim="name"></div></div>` (or `--anim`), with the scene in `js/anims/<name>.js`. See `.claude/skills/paper-diagrams.md` (still) and `.claude/skills/add-animation.md` (animated). Link `../css/anim.css` and `../js/anim.js` once on the page. Reuse an existing scene before drawing a new one.
- **DFDs and structure charts**: `<div class="nesa-diagram" data-diagram="key"></div>` with data in `js/nesa-diagram-data.js` (append keys with your prefix at the end of the object).
- **Mermaid** only where a skill allows it: pre-render with `npm run diagrams`.
- New scene files and data keys carry the page prefix: `im-`, `net-`, `cyber-`, `ds-`, `dv-`, `is-`, `ep-` (Resources: `tk-`, `pg-`, `ex-`).
- Notation follows the Course Specifications: system flowchart symbols, DFDs, flowcharts with BEGIN/END and labelled decision exits, decision trees, storyboards, network diagrams, graph theory, Gantt charts, schemas.

### 10  Storage keys and assets

- Any `localStorage` / `sessionStorage` key starts with **`ec-`**; wrap access in try/catch. (The site shares an origin with the Software Engineering site.)
- No external JS or CSS libraries and no CDNs. Optional page-specific styles or scripts go in `css/pages/<slug>.css` and `js/pages/<slug>.js`, linked only from your page and using the theme's custom properties.
- Keep to relative paths: pages in `topics/` use `../css/`, `../js/`, `../index.html`; the home page uses bare `css/`, `js/`; `404.html` uses site-absolute `/HSC_EnterpriseComputing/…` paths. Never use bare `/css/` paths.

## Checks (all must pass)

```bash
python3 scripts/site-chrome.py
python3 scripts/build-glossary.py
python3 scripts/build-mapping.py
python3 scripts/check-site.py --strict
bash scripts/validate-alignment.sh
```

(`--strict` fails while any `<!-- CONTENT: -->` placeholder remains; without it they are listed as notes.) Then preview (`python3 -m http.server 8000`) and screenshot in light and dark mode at 1400 px and 390 px: no horizontal scroll, figures readable, no console errors.

## Gotchas

- **Do not** hand-edit nav, footer, pager, icons or `?v=` values: run `site-chrome.py`.
- **`build-mapping.py`** reads section ids from each page, so run it after changing sections or headings.
- **Section ids**: each `<section id>` must match its sidebar `href="#…"`; `check-site.py` compares them in order, and expects one `sidebar-label` per NESA subheading.
- **Outcome subtitle**: write `<p class="outcome-subtitle">🎯 <em>(EC-12-01, EC-12-02)</em></p>` literally; `main.js` turns the codes into badges, and its outcome descriptions must match the syllabus file.
- **Bold a term once per paragraph**: `check-site.py` rejects a repeated bolded term (and its plural) in one paragraph or list item.
- **DOCTYPE**: every page must open with `<!DOCTYPE html>` (the deploy workflow checks).
- **Copyright**: never add the Course Specifications PDF or `resources/spec-pages/` images to the published site; link to NESA's official copy.
