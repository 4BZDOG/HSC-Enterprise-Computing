Why this matters now

Some of the marks in the HSC Enterprise Computing exam do not come from the focus-area dot points at all. They come from the Course Specifications, a short NESA document that spells out exactly how you must draw a data flow diagram, which SQL keywords you must know and which spreadsheet functions you must be able to use. NESA calls it “an integral part of the course content”, so a question can assume you know it.

The 2025 HSC did exactly that: students were asked to compare Level 0 and Level 1 data flow diagrams, write an SQL query with a join, build spreadsheet formulas, design a screen and schedule a team with a Gantt chart. Every one of those tools is on this page, in the order NESA lists them, with the page number so you can check it against the official document.

Try this as you learn Pick one thing you did today, such as buying lunch or booking a class. Sketch what data moved, who or what sent it and where it was kept. You have just started a data flow diagram.

Part 1 System and data modelling tools

Before anyone builds a system they draw it: what data moves, what logic runs, which devices are involved, what the screens look like and how the network is joined up. These eight tools (Course Specifications pp.4–11) are the drawings NESA expects, and each has a fixed set of symbols.

Ask yourself If you had to explain your school’s canteen ordering to a new developer, which of these drawings would you reach for first, and why?

Data Flow Diagrams (DFDs)

Course Specifications pp.4–5 Four symbols, the voting-system example and the Level 0 diagram

What it is for

A data flow diagram shows what data moves between the people and organisations outside a system, the processes inside it and the places data is kept. It does not show when things happen or how they are coded, which makes it the standard tool for agreeing requirements with a client. In NESA’s own Gantt chart example (p.12) “Produce a data flow diagram” is a task in requirements gathering.

NESA’s symbols (p.4)

Data flowLabelled, curved arrowData moving between processes, data stores and external entities. The label names the data, and the arrowhead shows the direction.Confirmation

Level 0 and Level 1 (p.5)

NESA describes a Level 0 diagram as an overview of the entire system that shows no data stores and no internal processes. The diagram above it on p.5, with three processes and two stores, shows the detail behind that overview. NESA does not name it, but the 2025 HSC called it a Level 1 diagram, so we do too.

How to draw one, step by step

We will build a diagram for an online ordering system in a school canteen. Students place an order and the canteen manager sets the menu and receives the order list.

  1. List the external entities: everyone and everything outside the system that sends or receives data. Here: Student and Canteen manager.
  2. Draw Level 0. Put one circle in the centre, name it for the whole system, place the entities around it and add a labelled flow for every piece of data that crosses the boundary.
  3. Break the system into processes. Name each circle for a job the system does, with a verb: Manage menu, Take order, Prepare order list.
  4. Add data stores wherever data has to be kept for a later process to use: Menu and Orders.
  5. Connect and label every flow. Label each arrow with the data itself (Order request, not “send”).
  6. Check the balance: every flow that crosses the boundary in Level 0 must appear, with the same label, in Level 1. Every process needs at least one flow in and one flow out.
Common exam mistakes Drawing data stores or several processes on a Level 0 diagram. Using a cylinder for a store or a rounded box for a process. Labelling flows with actions (“send”, “process”) instead of the data that moves. Leaving arrowheads or labels off. Joining two external entities or two stores directly. Showing a two-way exchange with one double-headed arrow instead of two labelled flows, as NESA does.
Exam tip The 2025 question on Level 0 versus Level 1 asked for the correct symbols. Award yourself marks for each thing a marker can see: correct symbol shapes, labelled arrows with heads, one process and no stores at Level 0, several processes and at least one store at Level 1. Then add one sentence saying what each level is for. If a question says “distinguish”, name a difference for each level rather than describing only one.
Try this A gym lets members book classes online. Members send a booking request and get a confirmation. Instructors receive a class list. The system keeps a Classes store and a Bookings store. Draw the Level 0 diagram, then the Level 1 diagram with at least three processes.
Model answer

Level 0: one circle (Class booking) with entities Member and Instructor. Flows: Booking request (Member to system), Booking confirmation (system to Member), Class list (system to Instructor). If instructors also set up the timetable, add Class details from Instructor.

Level 1: processes Set up class (Instructor sends Class details, written to the Classes store), Make booking (Member sends Booking request, reads Classes for Available classes, writes to the Bookings store, returns Booking confirmation) and Produce class list (reads Bookings for Booked members, sends Class list to Instructor). Check that all Level 0 flows appear in Level 1 with the same labels.

Flowcharts

Course Specifications p.6 Four symbols, read top to bottom and left to right

What it is for

A flowchart represents logic: the steps a process follows and the decisions along the way. It is what you draw when you must show how a rule works, such as when a delivery charge applies, before writing the program or formula that carries it out.

NESA’s symbols (p.6)

Input or output (parallelogram)Data coming in or going outEnter the delivery distance
Process (rectangle)An action or calculationNo delivery charge
Decision (diamond)A question with two possible answers, each leaving on a labelled arrowDelivery distance >10km?

How to draw one, step by step

  1. Write the rule in plain words and list every input the logic needs.
  2. Draw a START terminator at the top, then an input for each value you need.
  3. For each condition, draw a decision diamond with the question inside, using the same wording and symbols as the rule (“>10km?”).
  4. Draw two exits from each diamond and label both (Yes and No). Follow each one to a process or another decision.
  5. Bring separate paths back together where the logic joins, then finish with one END terminator.
  6. Trace the chart with test data for every path, including the boundary values.
Common exam mistakes Leaving a decision exit unlabelled. Using symbols NESA does not list for flowcharts (a subprogram box, connector circles, a system flowchart cylinder). Forgetting START or END, or drawing two ENDs. Putting a question in a process rectangle. Using a process box for something entered by the user, which belongs in an input/output parallelogram. Arrows without heads, so the direction is unclear.
Exam tip Test the boundaries. NESA’s example uses “>10km” for one decision and “≤$100” for another, so an order of exactly 10 km goes down the No path and an order of exactly $100 goes down the Yes path. Markers check that your comparison matches the rule.
Try this Draw a flowchart for a school library fine. Enter the number of days a book is overdue. If it is 0 or less, there is no fine. If it is more than 10 days, the fine is $5.00. Otherwise the fine is 50 cents for each day overdue. Output the fine.
Model answer

START, then input “Enter days overdue”. Decision “Days overdue ≤ 0?”. Yes leads to the process “Fine = $0”. No leads to a second decision “Days overdue > 10?”: Yes leads to “Fine = $5.00”, and No leads to “Fine = days overdue × $0.50”. All three processes flow into one output “Display the fine”, then END. Test with 0 days (no fine), 3 days ($1.50), exactly 10 days (No path: 10 × $0.50 = $5.00) and 11 days (Yes path: $5.00). Both paths give $5.00 at the boundary, which confirms the cap is applied consistently.

System Flowcharts

Course Specifications p.7 Nine symbols for the main processes and devices in a system

What it is for

A system flowchart shows the main processes and devices in a system: what is typed in, what is stored, what is displayed or printed and where data travels over a network. Where a flowchart shows the order of decisions, a system flowchart shows where the data goes. NESA says its arrows show “the direction of data between each of the symbols”.

NESA’s worked example

How to draw one, step by step

  1. List the processes the system carries out, in the order the data reaches them.
  2. For each process, list where its data comes from (online input, paper document, storage) and where its results go (storage, display, printout, cloud).
  3. Choose the correct symbol for each device or store and write a short name inside it: what the data is, or what the process does.
  4. Join symbols with arrows that point the way the data moves. Use a double-headed arrow when a process reads and writes the same store.
  5. Insert the telecommunications link where data crosses a network, for example to reach a cloud service.
  6. Check that every process has an input and an output and that every store is joined to a process.
Common exam mistakes Using flowchart symbols such as the decision diamond or terminator in a system flowchart. Arrows pointing the way the process happens rather than the way data travels. Labelling a symbol with a device (“hard drive”) when the question wants the data or file (“Customer file”). Drawing a plain arrow where data crosses a network instead of the telecommunications link. Using a symbol the question did not need, such as a magnetic tape, because it looked impressive.
Exam tip Match each part of the scenario to a symbol before you draw: typed by a person (online input), kept for later lookup (direct access storage), shown to someone (online display), printed (paper document), held on the internet (cloud). A marker is looking for the right symbol for each device and arrows in the right direction.
Try this A farm co-op takes orders online. A staff member types each order into the system. The system saves it to a customer file, shows a confirmation on screen and prints a packing list. Order totals are sent over the internet to an accounting service in the cloud. Draw the system flowchart.
Model answer

Online input “Order details” → process “Record order” (double-headed arrow to direct access storage “Customer file” if it checks the customer’s details) → online display “Order confirmation”, and → paper document “Packing list”. Process “Record order” → telecommunications link → cloud “Accounting service”. Only the nine NESA symbols are used and every arrow points the way the data travels.

Decision Trees

Course Specifications p.8 All the combinations of decisions and their resulting actions, in two layouts

What it is for

A decision tree lays out every possible combination of conditions and the action that results from each. NESA adds that each decision path leads either to another decision or to a final action. It is the tool for rules with several factors, such as the settings for a smart house or whether to buy a car.

NESA’s two forms (p.8)

How to draw one, step by step

  1. List the conditions (inputs) and the actions (outputs) the rule involves.
  2. Choose the first condition and make it the root. Each answer becomes a labelled branch.
  3. From each branch, add the next condition that matters for that branch, or a final action if the answer is settled.
  4. Make sure the branches from any one condition cover every possible value once: no gaps and no overlaps (for example >30, 15–30 and <15).
  5. Trace at least one path to every final action to confirm the tree gives the outcome the rule requires.
Common exam mistakes Drawing diamonds (NESA’s decision trees use rectangles). Leaving branches unlabelled. Ranges that overlap or leave a value out, so a reading of exactly 15°C fits two branches or none. A path that ends on a question instead of an action. Repeating a condition on a path that has already settled it.
Exam tip Give each path a quick check by reading it aloud as a sentence: “If the temperature is over 30 and the humidity is over 50%, then the fan is high.” If it does not read as a sensible rule, redraw that branch. The same tree can be written as IF–THEN rules, which is how the expert system section uses it.
Try this A school lends laptops. A student in Year 11 or 12 who has returned a signed agreement is issued a laptop. A student in Year 11 or 12 without an agreement is asked to sign one. A student in a younger year needs a teacher’s approval first; with approval they are issued a laptop, without it they are refused. Draw a vertical decision tree.
Model answer

Root: “Year 11 or 12?”. Yes leads to “Signed agreement returned?”, where Yes gives “Issue laptop” and No gives “Ask student to sign”. No (younger year) leads to “Teacher approval?”, where Yes gives “Issue laptop” and No gives “Refuse”. There are four paths, every branch is labelled and every path ends in a final action.

Data Dictionary

Course Specifications p.9 A comprehensive description of each field in a database

What it is for

A data dictionary describes every field in a database in enough detail that a developer could build the table and a data-entry operator could fill it in correctly. NESA says it commonly includes six things, and its table has exactly these six columns: field name, data type, data format, field size, description and example.

NESA’s own examples count field size slightly differently: the pay rate counts every character including the dollar sign and point, while the height counts only the digits. Whichever you choose, apply it consistently and say what you counted.

How to build one, step by step

  1. List each table, then every field in it. Use one row per field.
  2. Choose the data type by how the field is used. Text for names and for numbers you will never calculate with (phone numbers, postcodes). Date, Currency, Real and Boolean, as in NESA’s table, for the rest. Whole numbers are usually called Integer.
  3. Write the data format with X, N and #, or DD/MM/YYYY for dates, so the layout is unambiguous.
  4. Set the field size to the longest value the field must hold.
  5. Write a description that adds information, such as units or rules, rather than repeating the name.
  6. Give a realistic example that matches the format.

If a question also asks for validation, add a column for it. It is not one of NESA’s six, so treat it as an extension, as in our canteen example below.

Storyboards

Course Specifications p.9 The screens of an interface and the links between them

What it is for

A storyboard shows the various interfaces (screens) of a product and the links between them. You draw one before building a website or app so that the client and the team can agree on what each screen contains and how a user moves around.

NESA’s notation (p.9)

How to draw one, step by step

  1. List the screens the user needs and give each a title.
  2. Draw each screen as a rectangle with the same layout: title, Help button, navigation column, content panel.
  3. Sketch the content in each panel: headings, text lines, image boxes, tables. Detail is not needed; positions are.
  4. Show the navigation. Highlight the current screen’s button and draw an arrow from every button to the screen it opens.
  5. Number the screens and check every screen can be left: there must be a way back and an Exit.
Common exam mistakes Drawing screens with no links between them, which is a page of sketches rather than a storyboard. A different layout on each screen. No way home or to exit. Unlabelled buttons and controls. Spending the time on artwork instead of on labelled content areas and links.
Exam tip The 2025 HSC included an interface design question with form controls. Label every control by type (text box, drop-down list, check box, option buttons, button) and say what data it collects. Keep the layout consistent, and show navigation so a marker can follow the user from one screen to the next.
Try this Storyboard a three-screen app for a school library: Home, Search results and Book details. Show the buttons, which screen each one opens and where the Help button sits.
Checklist for your storyboard

Three screens with the same frame. Home has a search box and a Search button linked to Search results. Search results lists titles with a link to Book details on each. Book details shows the cover image box, the author, the availability and a Home button. Every screen has Help and Exit, and the current screen’s button is highlighted.

Network Diagrams

Course Specifications p.10 Symbols for the devices (nodes) and how they are connected

What it is for

A network diagram, also called a network map, documents a network: the devices (nodes) and how they connect. It is what you would give a technician who has to set up, extend or fix the network.

NESA’s notation (p.10)

DeviceRole in the network (our explanation)
RouterJoins networks together and passes traffic between the local network and the internet
HubA simple connection point that repeats what it receives to every device plugged into it
SwitchA connection point that sends data only to the device it is meant for. Most modern networks use switches where NESA’s example shows hubs.
Wireless deviceA device that connects without a cable, for example by Bluetooth or Wi-Fi
Computer, laptop, tablet, smart phone, printerEnd devices (nodes) that send or receive data

How to draw one, step by step

  1. List every device on the network, including the connection to the internet.
  2. Place the central device (usually the router) in the middle, and the internet above it.
  3. Add the hubs or switches, then group the end devices around the one they connect through.
  4. Draw a line for each connection. Use a different line style for wireless connections and add a small key if you use more than one line style.
  5. Label every device with its type, and its name or purpose where that helps (for example “Printer – front office”).
Common exam mistakes Icons with no labels. Devices left floating with no connection. Connecting every device straight to the router when the scenario says they share a hub or switch. Leaving out the internet connection. Mixing up wired and wireless devices with no key.
Exam tip The marker cares about correct devices, correct connections and clear labels, not about artistic icons. A labelled box for each device is fine. Draw the topology exactly as the scenario describes.
Try this A small office has a router connected to the internet. A switch connects a printer and four desktop computers. Two laptops and a phone connect to the router by Wi-Fi. Draw and label the network diagram.
Model answer

Internet at the top, joined to Router. From Router: one wired line to Switch and three dotted wireless lines to Laptop 1, Laptop 2 and Phone. From Switch: five wired lines to Printer and Computer 1 to 4. Every device is labelled and a small key shows wired (solid) and wireless (dotted) lines.

Graph and Network Theory

Course Specifications p.11 Nodes and links, applied to the design of social networks

What it is for

Graph and network theory represents things and the relationships between them. NESA says it can be applied in the design of social networks: people and groups become circles, and their connections become lines. Drawing the network makes it easy to see who or what is central and which groups cluster together.

NESA’s notation (p.11)

SymbolNameRepresents
CircleNode (vertex)An individual or a category. Its size may show the size of a dataset, where appropriate.
Straight lineLink (edge)A connection between nodes, groups of nodes or clusters. A label on the link names the relationship.

Reading the graph: the number of links at a node shows how connected it is, a cluster is a group of nodes mostly linked to each other, and a node that joins two clusters is a bridge between them. NESA does not name these ideas, but they are how a graph is interpreted.

Extension: numbers on links Some graphs put a number, called a weight, on each link, such as the cable length between two sites. NESA’s symbols do not include weights, so use them only if a question asks.

How to draw one, step by step

  1. List the nodes: the individuals and the categories in the network.
  2. Decide which links exist and what each relationship is called.
  3. Place the most important node in the centre and draw it largest if size is used to show importance.
  4. Draw straight lines between related nodes and write the relationship on each line.
  5. Group related nodes near each other so clusters are visible.
Common exam mistakes Circles with no labels. Links with no relationship written on them. Varying node size without saying what it means. Using arrows, boxes or other shapes (NESA’s symbols are circles and straight lines). Confusing a network diagram of devices with a graph of relationships.
Exam tip Say what each node represents and what a link means, then interpret: name the most connected node and explain why that matters for the design of the social network, for example who to notify or which group to promote to.
Try this Draw a graph of your class group chat. Put yourself in the centre, link to four classmates and two categories (a sport and a subject) and label each link with the relationship.
What a good answer shows

Your circle is the largest. Four individual nodes and two category nodes each have a straight link to you, labelled (for example Friend, Plays, Studies). Any two classmates who also know each other are linked, forming a cluster. You can explain which node has the most links and what that tells you.

Part 2 Project management tools

A project runs late one day at a time. NESA lists two tools for staying in control (Course Specifications pp.12–13): a Gantt chart, which plans and tracks the work, and a process diary, which records what actually happened.

Think about a group project How would you know, halfway through, whether your team is on schedule? What would you look at?

Gantt Charts

Course Specifications p.12 Tasks on a dated timeline, with dependencies, milestones, resources and progress

What it is for

Part 3 Implementing and testing a system

A system that passes every test in the workshop can still fail on its first morning in the real world. NESA names four ways to switch a new system on and six ways to test it (Course Specifications pp.14–15), and expects you to recognise each one and understand it.

Think about it If your school replaced its timetable system overnight, what would you want tested first, and what would you want to keep as a fallback?

System Implementation Methods

Course Specifications p.14 Recognise and understand: direct, parallel, pilot and phased

NESA names, we define NESA lists these four methods by name only and gives no definitions. The definitions, comparisons and examples below are ours, written to match how the methods are normally described.

What it is for

Implementation is the step where a new or redesigned system replaces the old one, or is put into use for the first time. The method you choose decides how much risk you take, how much it costs and how long the changeover lasts.

The four methods

MethodHow it worksStrengthsWeaknesses
DirectThe old system is switched off and the new one switched on at an agreed moment.Fastest and cheapest. Everyone moves at once.Highest risk. If the new system fails there is nothing to fall back on.
ParallelOld and new systems run side by side for a period. Outputs are compared before the old system is retired.Lowest risk. The old system is a safety net and results can be checked.Costs the most and takes longer: staff enter data twice and run two systems.
PilotThe complete new system is introduced in one location or one group first. If it works, it is rolled out to everyone else.Problems are found on a small scale. Feedback shapes the wider rollout.Slower overall. The organisation runs two systems for a while, and the pilot group may not represent everyone.
PhasedThe new system is introduced one part (module or function) at a time, for everyone, until all of it is live.Spreads the risk and the training load. Each stage can be fixed before the next.Old and new must work together during the changeover, which can be complicated. Full benefits come late.

Choosing a method for a scenario

ScenarioBest fitWhy
A regional hospital changes its patient records systemParallelFailure is unacceptable, so the old system stays as a fallback while results are compared.
A retail chain with 40 stores introduces new point-of-sale softwarePilotTrial in one store, fix the problems, then roll out to the rest.
A council adds new modules to its system: rates, then permits, then librariesPhasedEach module goes live in turn and staff are trained a module at a time.
A small sports club replaces its membership spreadsheet with a simple appDirectLow risk, cheap, and the old spreadsheet can be kept as a backup copy.

How to choose, step by step

  1. Ask how critical the system is. If failure is costly or dangerous, lean towards parallel or pilot.
  2. Ask how many users and locations are involved. Many sites suggest pilot or phased.
  3. Ask whether the system splits into independent modules. If it does, phased is possible.
  4. Weigh cost and time. Parallel is safest but most expensive, and direct is cheapest but riskiest.
  5. Justify the choice with a reason drawn from the scenario, and name the disadvantage you are accepting.
Common exam mistakes Mixing up pilot and phased. Pilot means the whole system in one place first, while phased means one part at a time everywhere. Calling parallel “cheap”. Naming a method with no reason from the scenario. Ignoring the drawback of the method you chose.
Exam tip For a “recommend” or “justify” question, name one method, give a reason from the scenario (risk, cost, number of users or whether the system is critical), and acknowledge one disadvantage. Two or three connected sentences earn more than a list of all four methods.
Try this A logistics firm with depots in five towns is replacing its parcel-tracking system. Drivers rely on it every hour, and the firm cannot afford lost parcels. Recommend an implementation method and justify it.
Model answer

A pilot in one depot, followed by a rollout, is a sound choice. It limits the damage if the system has faults, because only one depot is affected, and drivers’ feedback can be used to fix problems before the other four depots switch. The trade-off is a slower changeover and running two systems at once. Running the old system in parallel at the pilot depot would reduce the risk further, at extra cost.

Relational Databases: Normalisation and Schemas

Course Specifications p.16 Minimising duplication with linked tables, and drawing the schema

Normalisation

NESA describes normalisation as a process in relational database design where data duplication is minimised by separating the database into a number of smaller, linked tables. Each table should include fields that are solely dependent on the primary key in that table. NESA gives the reason: if a database contains redundant data, the copies may not be updated consistently, which leads to a data integrity problem. NESA does not ask you to name normal forms such as 1NF, 2NF or 3NF.

The problem: one flat table

The fix: separate, linked tables

Move each repeating group into its own table, give each table a primary key and link the tables with a foreign key. Now “Games Inc” is stored once, and each game holds only the Publisher_ID that points to it.

Primary keyA field whose value is different for every record in the table, so it identifies that record. It is marked (P) in NESA’s schema.
Foreign keyA field in one table that holds the primary key value of a record in another table, forming the link. It is marked (F).
RelationshipThe link between two tables. One publisher has many games, so the relationship is one-to-many, written 1 at the one end and ∞ at the many end.

SQL Syntax

Course Specifications p.17 SELECT, FROM, WHERE and ORDER BY, applied to the games schema

What it is for

NESA describes Structured Query Language (SQL) as a language used to access and manipulate data in relational databases. For the HSC Enterprise Computing course, NESA lists exactly four pieces of standard syntax:

  • SELECT (what is to be displayed)
  • FROM (the tables to be used)
  • WHERE (the search criteria which may come from multiple tables)
  • ORDER BY (the sequence in which the results are displayed)

NESA’s own examples also use AND to combine criteria, the comparison operators =, >= and <=, ASC and DESC after ORDER BY, and the Table.Field form for naming a field. The database software specification (p.19) adds the logical operators AND, OR and NOT, which you can use in a WHERE clause.

What NESA does not list The specifications do not list JOIN…ON, COUNT, SUM, AVG, GROUP BY or statements that change data such as INSERT, UPDATE and DELETE. In NESA’s examples a join is written by listing the tables in FROM and matching the linked fields in WHERE. Stick to the four keywords; anything else on this page is labelled as an extension.

The shape of a query

Pattern
SELECT   the fields to display
FROM     the table or tables that hold them
WHERE    the criteria a record must meet          (optional)
ORDER BY the field to sort on, then ASC or DESC   (optional)

The clauses always come in this order. Text and dates go inside single quotes. Numbers do not. If two tables have a field with the same name (Name appears in Games and Publishers), write Table.Field so the database knows which you mean. ASC (A to Z, smallest first) is the default, and DESC reverses it.

How to write a query, step by step

  1. Underline what the question wants displayed. Those fields go after SELECT.
  2. Find which tables hold those fields and any field named in the criteria. Those tables go after FROM.
  3. If you need more than one table, add a WHERE condition for each link: the primary key of one table equals the foreign key of the other. You need one fewer join condition than tables.
  4. Add the search criteria with AND (both must be true), OR (either) or NOT, using brackets when you mix them.
  5. Add ORDER BY with the field and ASC or DESC.
  6. Read the query back in words and check it against the question.
Extension (not in NESA’s list): JOIN…ON Many database programs also accept a JOIN keyword. This query returns the same rows as query 8. You will not be required to write it, but you may meet it in real software:
SQL (extension)
SELECT Games.Name, Publishers.Name
FROM Games JOIN Publishers ON Games.Publisher_ID = Publishers.Publisher_ID
ORDER BY Games.Name ASC

FROM Games, Publishers
WHERE Cost > 20
ORDER BY Cost
Model answer

First, Name exists in both Games and Publishers and is not qualified, so the database cannot tell which is meant: write Games.Name, Publishers.Name. Second, there is no join condition, so every game is paired with every publisher: add WHERE Games.Publisher_ID = Publishers.Publisher_ID AND Games.Cost > 20. Also, the sort should be written ORDER BY Games.Cost DESC if the most expensive is to come first, because ASC is the default.

Machine Learning and Statistical Modelling

Course Specifications p.18 Know what they are used for; the underlying logic is not required

What NESA expects

NESA says that machine learning and statistical modelling can be used independently or together to analyse datasets and make predictions. Students are not required to understand the underlying logic of either, but should be aware of their use in real-world scenarios. So the exam tests whether you can recognise a suitable use and describe it, not whether you can calculate a model.

NESA names, we describe NESA gives no definitions here. The descriptions below are ours, kept to the depth NESA asks for.
Statistical modellingMachine learning
IdeaFit a chosen mathematical model to data to describe the relationship between variables and to estimate or predict a value.A program learns patterns from example data, then uses them to predict or classify new cases.
Typical useEstimating how one thing changes with another, with a measure of uncertainty.Sorting or predicting from many inputs, especially when the patterns are hard to write as rules.
ExampleA council predicts next month’s water use from temperature and rainfall.A bank system flags card transactions that look unusual compared with past ones.
Used togetherA hospital could use a statistical model to estimate a patient’s risk from age and test results, and a machine learning model to spot patterns in scans, then combine both to support a clinician’s decision.

Both depend on the quality of the data they are given. Poor, biased or out-of-date data leads to poor predictions, which is why the ethical use of these tools is covered under Intelligent Systems and data quality under Data Science.

Common exam mistakes Writing about how the algorithms work when the question only asks for a use. Saying machine learning “thinks” or is always correct. Treating a prediction as a certainty. Forgetting that the two can be used independently or together.
Exam tip For a scenario question, name the technique (statistical modelling, machine learning or both), say what data it analyses, and say what it predicts and who uses the prediction. One sentence for each is enough.
Try this A farm co-op wants to predict next season’s wheat yield from rainfall records, and also to sort photos of grain samples by quality. Which task suits statistical modelling, which suits machine learning, and could the two be combined?
Model answer

Predicting yield from rainfall suits statistical modelling: it estimates how yield changes with rainfall. Sorting photos by quality suits machine learning, because a model can learn from labelled examples. They can be combined: the predicted yield and the quality mix together help plan sales.

Relational operators and IF

NESA lists the relational operators less than or equal to (<=), equal to (=), not equal to (<>), greater than (>) and greater than or equal to (>=). Less than (<) works the same way. They give TRUE or FALSE, which is what IF tests. IF can be nested to handle more than two outcomes, and it can be combined with the other functions:

Two things to remember about lookups. With FALSE as the last input, VLOOKUP needs an exact match and gives an error if there is none. With TRUE, the first column must be sorted in ascending order, and it returns the row for the largest value that is not more than the one you are looking up. That is why 120 points falls in the 100-point band.

How to build a formula, step by step

  1. Say in words what the cell must show, for example “total revenue after the loyalty discount”.
  2. Choose the function or operator that does each part: SUM for the total, VLOOKUP for the discount, IF for any condition.
  3. Decide which references must stay fixed when copied. Put dollar signs on those (an absolute reference) and leave the rest relative.
  4. Type the formula, then check it on test data whose answer you already know.
  5. Fill down or across, then spot-check the last row to confirm the references moved as intended.
Common exam mistakes Forgetting the =. Using a relative reference for a fixed value such as a rate, so the answer changes as you fill down. Range typos such as SUM(D2:D5) that miss the last row. Using COUNT on text (it counts numbers only). A lookup with the wrong match type: FALSE for an exact match, TRUE for a band. Putting text in a formula without quotation marks. Typing a value into a formula instead of referring to its cell.
Exam tip The 2025 HSC asked for formulas using SUM, LOOKUP and IF, and tested them with test data, and it asked about conditional formatting, pivot tables and choice of chart. Write the formula exactly, with the cell references from the question. Then show the value it would produce for a row of test data to prove it works. For chart questions, match the chart to the data: trend over time is a line, parts of a whole is a pie.

Expert System Software

Course Specifications p.20 Develop IF–THEN rules, change them, and display the rules used as text and as a decision tree

What NESA lists

Expert system software should allow you to develop a set of IF–THEN rules, add, remove and edit rules and display the rules the system has used to reach a conclusion, both in a text format and as a decision tree. An expert system stores the knowledge of a human specialist as rules and applies them to the facts a user provides, so a non-expert can get expert-style advice. The rules and the reasoning make it different from a database: it draws a conclusion, it does not just retrieve a record.

Rules, and the tree they make

Here are five IF–THEN rules for a laptop help-desk expert system:

RuleIFTHEN
R1Power light is on AND screen shows a picture AND Wi-Fi is connectedNo fault found
R2Power light is on AND screen shows a picture AND Wi-Fi is not connectedRestart the Wi-Fi adapter
R3Power light is on AND screen does not show a pictureConnect to an external screen
R4Power light is off AND charger is plugged inTry a different charger
R5Power light is off AND charger is not plugged inPlug in the charger

When the user answers the questions, the system can show why it reached its conclusion. In text: “Power light on = Yes. Screen shows a picture = Yes. Wi-Fi connected = No. Rule R2 fired: restart the Wi-Fi adapter.” As a decision tree, it highlights the path that was followed.

How to build and maintain a rule set, step by step

  1. Identify the decision the system must support and the questions the user can answer.
  2. Write each rule as IF conditions THEN conclusion, with one rule for each possible outcome.
  3. Check that every combination of answers fires exactly one rule: no gaps and no conflicts.
  4. Test with real cases and compare the system’s advice with what an expert would say.
  5. Edit as needed: add a rule for a new case, edit a rule whose advice is wrong and remove a rule that no longer applies. For example, add R6: IF the battery is swollen THEN stop using the laptop and take it to IT.
Common exam mistakes Rules with the same conditions but different conclusions, so the system contradicts itself. Gaps where a combination of answers matches no rule. Writing conclusions as questions. A displayed explanation that does not match the rules used. Forgetting to check the whole rule set after an edit.
Exam tip If a question gives you a decision tree, you can write the rules by reading each path. If it gives you rules, you can draw the tree. Show both forms when asked to “display” how a conclusion was reached, and mention that being able to add, remove and edit rules keeps the system up to date. See Intelligent Systems for how expert systems fit into decision-making.
Try this A farm co-op wants an irrigation adviser. Write four IF–THEN rules using soil moisture (dry or moist) and rain forecast (rain or no rain). Then add a rule for very high temperatures.
Model answer

R1: IF soil is dry AND rain is forecast THEN wait and re-check tomorrow. R2: IF soil is dry AND no rain is forecast THEN irrigate. R3: IF soil is moist AND rain is forecast THEN do not irrigate. R4: IF soil is moist AND no rain is forecast THEN check again in two days. New rule R5: IF temperature is above 35°C AND soil is dry THEN irrigate even if rain is forecast. Because R1 and R5 now overlap, edit R1 to say AND temperature is 35°C or lower, so the rules do not conflict.
